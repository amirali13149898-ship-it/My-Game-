# اردیان — بات تلگرام PvP فانتزی (Go + SQLite)

## اجرا
```bash
go mod tidy                      # بار اول: درایورهای sqlite/pgx و go.sum رو می‌سازه (go.sum رو کامیت کن)
cp .env.example .env && export $(grep -v '^#' .env | cut -d' ' -f1 | xargs)
go test ./... && go run ./cmd/ardian
```

## دیتابیس: Supabase (Postgres) یا SQLite
بات دو دیتابیس رو می‌شناسه و با متغیر `DATABASE_URL` انتخاب می‌کنه:
- **`DATABASE_URL` ست باشه** (آدرس `postgresql://...`) ← Postgres (Supabase). جدول‌ها و migrationها اولین اجرا خودکار ساخته می‌شن.
- **ست نباشه** ← فایل SQLite (`DB_PATH`)، مناسب اجرای لوکال.

### راه‌اندازی Supabase
1. تو supabase.com یه پروژه بساز و رمز دیتابیس رو یادداشت کن.
2. بالای صفحه **Connect** ← **Session pooler** (پورت **۵۴۳۲**) ← آدرس رو کپی کن.
   - Session pooler رو بزن، نه Direct connection: آدرس Direct فقط IPv6 داره و ممکنه از Railway وصل نشه.
   - اگه رمزت کاراکتر خاص داره (`@ : / # %`) تو آدرس باید URL-encode بشه (مثلاً `@` ← `%40`).
   - Transaction pooler (پورت ۶۵۴۳) هم کار می‌کنه؛ بات خودش حالت `simple_protocol` رو ست می‌کنه.
3. این آدرس رو تو Railway به‌عنوان متغیر `DATABASE_URL` بذار. **Volume لازم نیست.**
4. امنیت: migration سوم روی همهٔ جدول‌ها RLS فعال می‌کنه (بدون policy) تا Data API سوپابیس با کلید `anon` به دیتای بازی دسترسی نداشته باشه؛ بات با نقش `postgres` وصل می‌شه و تحت‌تأثیر نیست. این رو خاموش نکن.
5. بکاپ: Supabase خودش بکاپ داره (بکاپ‌های خودکار طبق پلن). بکاپ زمان‌بندی‌شدهٔ بات فقط برای SQLite کار می‌کنه و با Postgres خودش رو غیرفعال می‌کنه.

## دیپلوی روی Railway
1. ریپو رو روی GitHub بذار و تو Railway «Deploy from GitHub repo» بزن (Dockerfile خودکار شناخته می‌شه).
2. Variables: `BOT_TOKEN`، `ADMIN_ID`، `DATABASE_URL` (Supabase). *(اگه SQLite می‌خوای: یه Volume روی `/data` مانت کن و `DATABASE_URL` رو نذار.)*
3. تو BotFather: `/setprivacy` ← **Disable** (تا بات پیام‌های گروه رو ببینه).
4. قبل از اولین دیپلوی یک بار `go mod tidy` بزن و `go.sum` رو کامیت کن.
بات long-polling استفاده می‌کنه؛ پورت یا دامنه لازم نیست. تو لاگ باید `database: PostgreSQL` و `bot @... started` ببینی.

## وضعیت: کامل (هر چی سند تعریف کرده ساخته شده)
- **هسته:** بستر، ۱۸ کارکتر، فرمول استت‌ها، ساخت کارکتر، منوها، ۸۰ ابیلیتی عنصری، ۹ ابیلیتی نژاد، چرخهٔ عنصری، حمله با ریپلای، کولداون‌ها، XP/طلا/لول، ادمین.
- **اقتصاد:** 🛒 شاپ، 🎒 تجهیزات (۱۰ اسلات)، 🐗 شکار با دراپ، 🏯 دانجن، 🏆 لیدربرد، ⚔️ کلن.
- **مرگ و ریست:** جریمهٔ مرگ، ♻️ ریست استت.
- **عکس‌ها:** کش با هش + file_id، پوشهٔ `assets/` یا `/setphoto`.
- دیتابیس با migration (`PRAGMA user_version`)؛ دیتابیس نسخه‌های قبلی خودکار ارتقا پیدا می‌کنه.

## تصمیم‌های پیش‌فرض بخش‌هایی که سند «هنوز مشخص نیست» گذاشته بود (همه قابل تغییره)
- **سلاح اصلی**: دمیج ثابت (`۲۵×tier^1.4×ضریب‌کمیابی`) به دمیج فیزیکی اضافه می‌شه و ۳۰٪ش هم به جادو.
- **آیتم‌ها**: ۹ نوع × ۱۰ تیر × ۵ کمیابی، هر کدوم ۲ استت. لول لازم = `۱+(تیر−۱)×۱۰`. بونوس تجهیزات روی استت مؤثر جمع می‌شه ولی سقف خرج امتیاز فقط روی پایه+امتیاز حساب می‌شه.
- **اسلات‌ها**: زره ۱، سلاح اصلی ۱، کلاه ۵، کفش ۱۰، شلوار ۱۵، دستکش ۲۰، ماسک ۲۵، سلاح فرعی ۳۰، حلقه ۱=۴۰، حلقه ۲=۶۰ (`SlotUnlock`).
- **قیمت**: `۴۰×tier²×ضریب‌نوع`؛ فروش ۴۰٪؛ فقط آیتم معمولی از شاپ.
- **شکار**: ۳ هیولا؛ نبرد ثانیه‌به‌ثانیه با همون موتور PvP روی کلون شبیه‌سازی می‌شه؛ هر ۱۵ ثانیه.
- **دراپ**: جدول ۱۲ آیتمی برای هر هیولا؛ حداکثر ۱ آیتم؛ شانس +۰٫۵٪ نسبی/امتیاز روی کمیاب‌ها؛ فرشته ۳ کمیاب‌ترین رو ضریب می‌ده.
- **دانجن** (`game/dungeon.go`): ۵ طبقه + باس، HP/مانا بین طبقه‌ها بازیابی نمی‌شه، بعد از هر طبقه می‌تونی با غنیمت بری؛ مرگ = از دست رفتن غنیمت + جریمهٔ مرگ.
  شرط ورود: لول ۱۰، حداقل ۵۰٪ HP، ۱۰ دقیقه فاصله. (وضعیت دانجنِ در جریان تو حافظه‌ست؛ با ری‌استارت بات رها می‌شه.)
- **جریمهٔ مرگ**: ۱۰٪ طلا و ۲۵٪ XPِ لول فعلی می‌سوزه (به قاتل نمی‌رسه، لول کم نمی‌شه) — `DeathGoldLossPct`, `DeathXPLossPct`.
- **ریست استت**: بار اول رایگان، بعد `۱۰۰×لول` طلا؛ همهٔ امتیازهای خرج‌شده برمی‌گردن.
- **کلن**: بدون بونوس؛ ساخت = لول ۱۰ + ۱۰۰۰ طلا، ظرفیت ۳۰.

## یافتهٔ بالانس (مهم — قبل از انتشار بخون)
با `BALANCE=1 go test -run 'RaceMatrix|SweepShare' -v ./internal/game` داشبورد بالانس اجرا می‌شه (دوئل‌های شبیه‌سازی‌شده، لول ۲۰/۶۰/۱۰۰):
- **بیلد فیزیکی ≈ ۹۵–۱۰۰٪ بیلد جادویی رو می‌بره.** علت ساختاری: «قدرت» تنها استت دمیجه (جادو فقط ۳۰٪ش رو می‌گیره)، حملهٔ فیزیکی مانا نمی‌خواد و کولداونش (۵s) برابر فایربال (۵s) ـه؛ مانا/کنترل فقط جریمه کم می‌کنن و دمیج اضافه نمی‌دن. بالا بردن `MagicPowerShare` تا ۱٫۵ هم مشکل رو حل نکرد.
- نژادها: نیمه‌گرگ/اژدها/ببر و دورف ۶۰–۹۰٪، الف/فرشته/دارک‌الف ۱۷–۴۱٪ (فرشته‌ی PvP بی‌ارزشه چون پسیوش درآمدزاییه).
- این همون «لیست تعادل» سنده؛ پیشنهاد: یه استت/ضریب دمیج جادویی (مثلاً از کنترل یا مانا) یا کاهش دمیج فیزیکی (`PhysPerPower`) اضافه بشه. من چیزی خارج از سند عوض نکردم تا خودت تصمیم بگیری.
- توانایی‌های فعال نژاد (کیوبی، زتسو، ...) تو شبیه‌ساز AI استفاده نمی‌شن؛ فقط پسیوها.

## تفسیرهایی که از سند کردم (تو `internal/game/types.go` و `combat.go` عوض‌شدنیه)
- **قدرت روی جادو ۳۰٪**: `قدرت×۲۰×۰٫۳` به دمیج جادو اضافه می‌شه.
- **بازهٔ حملهٔ فیزیکی** ±۱۰٪ (سند مقدار نداده).
- **کنترل**: اختلاف مانا−کنترل ≥ ۵ → هر واحد ۲٪ (سقف ۵۰٪) هم مصرف مانا رو زیاد و هم دمیج جادو رو کم می‌کنه.
- **ریکاوری**: ۵۰ در دقیقه × (۱ + ۰٫۰۳×سرعت).
- **جاخالی**: `max(0, امتیاز مدافع − امتیاز مهاجم)` + بافرهای جاخالی − بافرهای دقت (سقف ۹۵٪).
- **شارژ بافرها**: بافرهای مهاجم فقط با ضربهٔ موفق مصرف می‌شن (به جز «فایر رایتو» که با جاخالی هم مصرف می‌شه)؛ بافرهای دفاعی با هر ضربهٔ نشسته؛ جاخالی-بافرها با هر حمله.
- **بافرها** بعد از ۶۰ ثانیه می‌سوزن (کیوبی، کوکتسو، زتسو هم).
- **زتسو**: شانس = لول (مؤثر)٪؛ اگه کریتیکال طبیعی هم بیاد ضریب ۴x می‌مونه.
- **لول مؤثر نژاد**: هر لول نژاد باید با طلا خریده بشه؛ لول ۱ رایگانه (به جز دارک‌الف که از ۵۰۰ شروع می‌شه).
- **شینگو (گرگ)**: استک با ضربه‌های موفقِ خودش؛ دمیج = استک×درصد روی همهٔ حمله‌ها.
- **ردیف دکمه‌های استت**: ترتیب «صفر | نام | +۱ | −۱ | +۱۰» راست‌به‌چپ خونده شده.
- رنگ دکمه‌ها از فیلد `style` تلگرام (primary/success/danger) استفاده می‌کنه؛ اگه کلاینت نشناسه نادیده می‌گیره.

## مصرف منابع (برای پلن‌های رایگان)
- متن‌ها و عکس‌های منو فقط یک‌بار از دیتابیس خونده می‌شن و کش می‌شن (با `/settext` و `/setphoto` کش پاک می‌شه).
- بازیکن‌هایی که ۱ ساعت فعالیت نداشتن از حافظه حذف می‌شن (همه‌چیز قبلاً ذخیره شده؛ دفعهٔ بعد از دیتابیس برمی‌گرده).
- اتصال به Postgres حداکثر ۲ تا، با بستن خودکار اتصال‌های بیکار.
- Go با `GOMAXPROCS=1 GOGC=50 GOMEMLIMIT=100MiB` اجرا می‌شه (رم کم).
- نکته: پروژهٔ رایگان Supabase بعد از چند روز بی‌استفاده‌بودن ممکنه pause بشه؛ چون بات هر چند ثانیه به دیتابیس سر می‌زنه معمولاً مشکلی نیست.
